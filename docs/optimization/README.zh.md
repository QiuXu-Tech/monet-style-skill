# Monet Style：可复用优化循环 V1.0

**2026-11-09｜适用基线：0.3.0-alpha.1｜计划版本不等于 Skill 版本**

目标：在不改变用户内容要求的前提下，提高莫奈画法的一致性、跨题材适应性和一次出图成功率，同时控制重试、费用、复杂度与隐私风险。稳定指绘画语言连贯，不指固定配色、固定构图或所有图都画睡莲。

这是一套按轮次执行的开发协议，不是已经启动的定时任务。它不自行调用生图服务、付费、训练模型或修改生产版本。当前 Skill 的真实视觉基准仍为 **NOT_RUN**；新增计划不能改变这个事实。

## 0. 从哪个状态开始

当前实施基线为提交 `a8af9d273f2bcd06670003f5ef027b121489394b`。原包包含两幅可核验风格参考、固定画法文本、输入锁及逐图验收记录。36 项工程测试已通过，本轮又在原实现目录中复跑通过；安装包完整性检查也通过。没有真实出图或视觉改善结果。[R1–R3]

参考库中的 163 条记录是检索资料，不是已经完成去重、艺术史核查和视觉标签确认的 163 个独立样本。现阶段先使用已有的 1880s 实验范围和两幅参考，不随意混入晚期睡莲、增加画风或启动 LoRA。[R4]

第一优先级是跑通**真实参考输入 → 真实出图 → 查看图片 → 记录验收**。禁止继续用新增提示词长度或测试数量代替图像证据。

## 1. 一轮的固定流程

```text
冻结基线 → 检查能力/预算 → 收集失败证据 → 选择一个问题
    → 预登记假设与判据 → 最小修改 → 小样 A/B
    → 通过才扩大回归 → 晋级 / 保留基线 / 回滚
    → 失败进入用例库，结论进入下一轮
```

| 阶段 | 必做动作 | 可核验产物 / 出口 |
|---|---|---|
| A. 冻结 | 固定基线、候选、宿主、参考图、规则版本和测试集 | 填写 round-plan；缺失字段不能进入正式比较 |
| B. 检查 | 工程测试、参考可见性、真实调用能力、输出可审看性、预算 | PASS / BLOCKED / NOT_SUPPORTED，不伪装成视觉失败 |
| C. 定位 | 查看原图和失败候选，区分内容、画风、泄漏、结构或工具问题 | 一个带图片位置证据的失败描述 |
| D. 假设 | 指定单一改动、主指标、保护指标、停止条件 | 在候选出图前锁定假设与接受门槛 |
| E. 修改 | 只改与假设相关的最小范围；保留基线 | 代码/规则差异、候选新锁、工程回归 |
| F. 比较 | 同任务、同后端、同输入角色，重复出图并随机呈现 | 全部候选、调用记录、匿名对照、逐项评分 |
| G. 判定 | 先检查硬失败，再比较目标改善及副作用 | PROMOTE_EXPERIMENTAL / KEEP_BASELINE / REVERT / INCONCLUSIVE |
| H. 留档 | 记录失败、变更原因、结果、成本和下一问题 | round-report；公开内容须脱敏 |

首个视觉基线轮 R001 是例外：它比较“普通莫奈提示”与“整个当前 Skill”，只回答 Skill 整体是否带来增益，不能归因到某一句提示或某幅参考。之后才开展单变量优化。

**“单变量”不等于只改一行代码。** 同一变更所必需的版本号、MANIFEST、测试更新可以一起改，但不得夹带新的锚点、模型、色板、重试策略等独立干预。

## 2. 每轮冻结什么

在 [round-plan 模板](templates/round-plan.json) 中登记：

- 基线和候选的 Git 提交、包哈希、画法契约哈希；基线必须仍可运行。
- 用户原始请求、逐项必须保留/禁止项、比例、内容图及其哈希。
- 参考原作身份 `artwork_group_id`、数字图 SHA-256、角色（STYLE / CONTENT），不可互换。
- 宿主、实际模型标识/快照（可取得时）、分辨率、采样与图像参数、执行时间窗口。后端不暴露的字段写 `undisclosed` 或 null，不猜测。
- 一项主要假设、最多一个候选、主要比较指标、不可退化指标、任务与重复次数。
- 预算、评审人/模型、预注册判断规则，以及出现不确定性如何停止。

修改画法/锚点/版本时，为候选建立**新的合法风格锁**，保留基线锁；不得关闭旧锁验证来让不同配置冒充同一个系列。系列内部不自动切锚点；跨锚点评估应独立标识各组。

模型或依赖变更需另建后端比较轮，不能同时调提示词并宣称提示词有效。封闭后端没有可固定快照时，采用同一时间窗口交错 A/B 调用并记录可取得的标识，结论标为“特定宿主/时间窗口的观察”。相同 seed 也不保证跨硬件、版本逐像素相同。[S2]

## 3. 数据集：开发、回归、保留测试分别管理

### 3.1 首批开发集

[development-cases.json](development-cases.json) 含 8 个文字生图用例：现代列车、三只杯子、两人左右关系、夜景阶梯、现代滨水建筑、无人物雪原、室内单只猫、无睡莲的河岸。每个用例的 `request` 子对象可直接交给现有 `prepare`；用例 ID 等外层元数据不能直接塞进严格的请求接口。

八个题目是**公开开发题**，不用于声称盲测泛化。新增失败任务应保留原始要求，不能为了让模型通过而删去数量、位置、夜晚或现代属性。

### 3.2 工作流回归

另保留三类流程检查，不混入文字生图统计：

1. 原图转绘：内容结构来源于用户实际提供且获授权的图，风格来源于独立参考。
2. 局部修改：在同一个已审看输出上仅修改一个要素，检查其余合格区域是否漂移。
3. 系列创作：同一内容的三个天气/时段变体保持画法身份，同时允许合理色彩变化。

内容照片、编辑起点尚未准备时，用例为 BLOCKED_FIXTURE，不虚构文件、不用莫奈原作冒充用户内容图。工作流测试所需前置生成也占预算。

### 3.3 发布保留集

发布前另准备 8 项未用于调参的任务，并按**原作身份**而非 Commons 文件 ID 划分参考素材。相同原画的扫描、翻拍、裁切必须在同一组；仅做文件哈希去重不够。

保留任务由未参与这轮调参的评审者准备更好；条件不足时明确记录“单人留出测试”，不冒充独立盲测。任务清单、参考组和评分规则须在生成前冻结。用于修正规则后，该批保留数据转为开发数据，重新准备下一批；不能反复查看它直到过关。

当前默认锚点锁定时，先只测**新题材泛化**。更换原作锚点的测试属于额外的参考鲁棒性实验，不强迫窄范围预设支持未声明的时期/锚点。

## 4. 阶梯预算：先小样，不默认跑满 180 张

| 阶段 | 任务 × 方案 × 独立重复 | 首轮生成输出上限 | 用途 |
|---|---:|---:|---|
| 冒烟测试 | 2 × 2 × 2 | 8 | 验证端到端可行性、发现明显失败 |
| 针对性 A/B | 4 × 2 × 3 | 24 | 验证一项改动的初步收益 |
| 跨题材回归 | 8 × 2 × 3 | 48 | 检查改善是否损伤其他题材 |
| 发布保留测试 | 8 × 2 × 3 | 48 | 独立任务上的观察性复核 |

这些是**实验设计上限，不是付费授权**。正常轮先授权/执行 8 张；结果值得继续才再申请/启用下一阶段。冒烟 + 针对性测试最多 32 张；全部四阶段完全重新采样上限 128 张，另行登记的修图、来源夹具、锚点或跨会话测试不在这个数中。

默认不复用旧生成作为新的随机样本。重复使用时必须注明样本 ID 与复用原因，只计一次；后端升级或时间窗口不可比时重建基线。

预算须有输出数、工具调用数和（可得时）货币三重限制。失败/超时调用可能计费，也记入调用/费用预算；费用不可得写 unknown，不能当作 0。“未批准额外付费”不禁止授权范围内已有宿主额度，但禁止新增付费 API、租 GPU、自动充值或下载重模型。

首轮生成质量不自动重试；比较的是每个独立请求的第一次输出。另设修复试验，最多两次额外尝试（总共三次），同时服从该轮更严格的预算。[R3]

## 5. 如何评审：内容正确与艺术质量不能相互抵消

### 5.1 硬性条件

逐项记录 pass / fail / unknown，并指出画面位置和依据：主体、数量、指定颜色、动作、左右关系、时段、禁止项、必要构图、比例与图片可解码性。

主体缺失、夜晚变白天、把现代列车变成蒸汽机车、复制参考独有的房屋/人物/签名，都不能用“更漂亮”抵消。用户本来要求画桥时，桥的存在本身不构成泄漏；要看是否搬运了参考图的特定桥形或布局。供应商依法/依约附加的溯源信息按宿主规定保留，不把去除溯源当成优化。

### 5.2 风格五维量表

分别评价现有契约的五个维度：色彩与光色关系、材质相关笔触、选择性边缘处理、空间/空气感、油画媒介质感。[R2]

建议量表：0=明显不符合，1=只有表面滤镜或泛化油画感，2=部分符合但明显漂移，3=大体符合选定参考语言，4=高度连贯且与题材自然结合。unknown 单列，不给 0 分、不当作通过。

**暂定单图风格合格线为五维均 ≥3。** 这是待校准的工程门槛，不是已有艺术史定论或验证结果。在 R001 的基线样本上校准后冻结；若日后改量表，基线与候选须一起重评，保留旧评分，不可以只放宽候选的标准。

评审看相同锚点、相同任务和同分辨率作品，候选使用随机编号，隐藏版本和方案名。随机左右次序；先逐图判硬条件，再做成对偏好评价。默认不允许只用模型自评给出稳定版结论；可用模型辅助定位，但发布阶段至少需要真实人工审看，条件允许再由第二位评审复核分歧。[S1]

当前 `ACCEPTED_REPORTED` 仅代表某位评审报告逐项通过，不代表机器独立验证艺术质量。这里的五维分数是附加实验记录，不改变现有 review 输入 schema。[R3]

### 5.3 不能省略的指标

| 指标 | 计算口径 |
|---|---|
| 技术完成率 | 有真实、可解码输出的请求数 / 计划且已发起的首轮请求数 |
| 首轮内容合格率 | 首次输出所有内容硬条件通过的任务实例 / 全部已发起首轮任务实例 |
| 首轮风格合格率 | 首次输出五维均达线的任务实例 / 全部已发起首轮任务实例 |
| 联合首轮成功率 | 同时满足技术、内容、风格、结构（适用时）且无明确泄漏 / 全部已发起首轮任务实例 |
| 参考内容泄漏率 | 有明确非需求原作内容迁入的首次输出 / 已完成视觉审看的首次输出，同时公布 unknown 数 |
| 修复成功率 | 两次额外尝试内修复且不损伤其他硬条件的失败实例 / 进入修复试验的失败实例 |
| 每个合格结果成本 | 同一评估批次全部调用费用 / 联合合格结果数；无合格图记不可用，不除以零 |
| 时间 | 真实生成和审查耗时分别记录；工具排队时间也保留，不用估计填充 |

报告全部分子/分母、缺失与 unknown 数，提供按任务类别的拆分。未审看样本不能加入成功数；同时给已审看子集结果，但不得只展示该子集掩盖缺失。每个任务保留等量首轮样本，不将 best-of-3 当作一次成功。

同一个题目多张图不是多个完全独立题目；重复用于观察波动，推断应以任务/原作组为单位。小样 A/B 只提供方向，不冒充总体显著改善。需要区间估计时以任务组重采样，报告组数和宽区间；不要把全部图片当独立样本得到虚假的精确性。

## 6. 优化问题的优先级和允许的改动

排序按“阻断程度 → 实际失败频率 → 影响用户内容的严重性 → 最小修复成本”，不先增加复杂模型。

| 错误类型 | 证据 | 优先尝试 | 不该一起改变 |
|---|---|---|---|
| TOOL / REF_INPUT | 没有输出、参考像素未送达 | 修宿主调用/附件映射，先测能力 | 不改美术规则掩盖接口问题 |
| CONTENT | 数量、方向、身份或天气不符 | 强化该条内容约束或受支持的局部修正 | 不换锚点和模型 |
| STYLE | 泛化油画、照片滤镜、统一噪声 | 针对一个画法维度改一段规则 | 不同时改全部五个维度 |
| LEAKAGE | 参考独有建筑、船队、人物被搬入 | 明确参考角色和泄漏排除项 | 不禁止用户原本需要的同类对象 |
| STRUCTURE | 用户原图关键关系丢失 | 修内容图映射/局部编辑；开放模型另行试验结构控制 | 不把风格原作当内容结构 |
| SERIES | 连续图片锚点/画法漂移 | 检查锁、宿主会话、参数与附图 | 不用强制同色板假装一致 |
| EFFICIENCY | 质量已合格但耗时/调用多 | 删除无证据贡献的规则或重复步骤 | 不降低内容验收线 |
| DATA | 同画不同扫描跨组、日期或授权存疑 | 修该条来源/分组；必要时隔离样本 | 不悄悄覆盖历史实验记录 |

开放模型的 IP-Adapter、ControlNet、LoRA 仅在本轮证据说明宿主方案不足且授权明确时另开实验；不作为普通 Skill 轮次的默认依赖。既有 180 图研究草案保留为可选机制研究，不被本计划自动启动。

## 7. 晋级、回滚与不确定性

以下为**建议初始工程门槛**，须在对应候选出图之前登记。不能看完结果后选择对候选有利的指标。

- **工程修复轮**：新增可重现失败测试，修复后通过，已有 36 项（后续可能增加）不退化；若影响生成输入，仍须视觉回归。只修打包/文档等不改变生成行为，可标 ENGINEERING_ONLY，但不能宣布画风改善。
- **画风优化轮**：针对性阶段 12 对首次输出中，至少 8 对明确偏好候选、至多 2 对偏好基线；未知/平局不算获胜。内容联合率不低于基线，不能新增关键内容失败或清晰泄漏。这只是进入扩大回归的筛选线，不是统计显著性。
- **内容优化轮**：目标失败在 12 个候选实例中至少减少 2 个；按类别不引入新的关键内容退化，五维画风不系统退化。若基线失败不足 2 个，须预先采用另一个合理、可检验的主指标，不临时更换目标。
- **效率轮**：先登记成本/时间改善目标及质量保护线；费用 unknown 时不宣称降低成本，保持质量优先。

所有候选均须通过跨题材回归后才能成为下一轮的**工程基线**。对确定性的硬 bug 零容忍；对随机视觉失败保留全部数据并检查是否新增失败模式，不凭一张差图判因果，也不凭均分掩盖严重问题。证据有冲突、样本缺失或评审明显分歧时选择 INCONCLUSIVE，不强行晋级。

发布视觉验证版前，另做冻结的保留测试，要求两个方案都完整评审；建议候选至少 22/24 联合合格、每个题目至少 2/3 合格、零明确参考内容泄漏，并需在另一执行会话复核。**该门槛是受限样本的观察线，不能推导出真实用户总体成功率 ≥90%。** 第二会话、新锚点或编辑验证的图数应额外登记预算；不默算进 128 张。

首次达到上述观察线时只能称“在列明后端、时期、任务集上经过视觉验证”。要扩大支持题材、后端或画风时期，必须另建分层证据，不能泛称所有平台稳定。

每轮最多一个候选；连续两轮同类假设无收益，暂停堆规则，重查参考、模型能力或评审标准。达到输出/调用/费用预算立即停止，记录 BUDGET_STOP；不无限选图。回滚保留失败分支和证据，只恢复上一批准基线，不能删除实验历史。

## 8. 前四轮具体安排

| 轮次 | 目标 | 输出与退出条件 |
|---|---|---|
| R000（已完成工程检查） | 冻结 Alpha、复跑测试、建立计划 | [基线记录](rounds/R000-baseline.json)；36 测试通过；视觉仍 NOT_RUN |
| R001（已准备，未执行） | 普通莫奈提示 vs 当前完整 Skill | [8 张冒烟计划](rounds/R001-plan.json)：杯子/夜景，两路各重复两次；验证真实出图和审查链 |
| R002 | 针对 R001 最大失败模式做一项改动 | 先复现，再 24 张针对性 A/B；无失败证据不预先填“优化已成功” |
| R003 | 将有收益的候选做 48 张跨题材回归 | 内容、画风、泄漏、成本分别检查；通过才晋级工程基线 |

之后复用 A—H 循环。不要把“轮数越多”当成果；没有有价值的失败或改进假设时保持基线，不为了周报改代码。

## 9. 运行状态与宿主限制

状态建议：DRAFT → READY → RUNNING → GENERATED_PENDING_REVIEW → REVIEWED → PROMOTE_EXPERIMENTAL / KEEP_BASELINE / REVERT / INCONCLUSIVE；能力不足为 BLOCKED_CAPABILITY，费用不足为 BUDGET_STOP。

如果宿主要求生图后立即结束，当前交互只完成到 GENERATED_PENDING_REVIEW；后续允许的交互再审看结果和填写报告。不得为“闭环”违反宿主工具规则，也不得假装已经查看尚未可访问的图片。无法取得输出文件时说明哪一项验证受限。

定时任务不能替代实际图像生成权限、费用授权和人工评审。本计划没有安装自动调度器；只有明确授权执行的轮次才运行，没有运行中的后台优化承诺。
