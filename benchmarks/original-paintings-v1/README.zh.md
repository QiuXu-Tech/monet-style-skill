# 莫奈原作对照评测协议 V1.1

**本次更新状态：PROTOCOL_UPDATED / VISUAL_VALIDATION_NOT_RUN。** 本次升级了编译输入与评审记录，没有生成新图、填写新分数或验证画风改善。既有 `cases.json` 与 `rounds/` 保持原样；历史实验状态不因协议更新而改变。

当前采用 `review-template.json` 的 **1.1.0** 协议。`validate.py` 仍能读取显式 1.0.0（以及未声明版本的旧格式）记录，并标明 `legacy_protocol=true`；不能将旧记录称为通过了新增的原作来源与复制风险检查。目标是形成可重复、有反例、不会制造虚假分数的评测程序。

## 本次执行方式

本项目的实际测试图由用户在**其他独立对话**生成，本对话只准备完整可复制提示词、接收图片和评审。不得在本项目研究/升级对话中调用图像生成工具；用户要提示词时直接给纯文本，不交付 ZIP/TXT 包。下文 CLI 产生的文件供本地工程核验与留档，不能被解释为授权生图。

## 1. 研究的真正问题

**不是**“新图与原画的船、人、草垛数量有多相似”，而是“面对同类题材与光照任务，新图是否具有莫奈作品中可辨识的笔触组织、光色关系与空气感”。

- 内容门槛：至少同一题材类型、相容的时间天气条件、独立单幅画；严重跑题、报告海报、双联画、意外文字直接 FAIL。另检查模仿签名和原作独特构图/对象组合的迁入。**内容相似程度不参与风格总分。**
- 主评估：笔触（30%）、色彩（30%）、氛围感（30%）、伪纹理控制（10%），每项 0–10 分，可保留半分。
- 原作中原本存在的短促、破碎笔触**不属于错误**；有问题的是无视天空/水/衣料/地面差异、同尺度重复铺满画面的 AI 鳞纹。
- 多幅作品的朦胧感应随内容变化：画面可以清晰到保留必要主体，却不应统一锐化或对全图做高斯模糊。
- 不强制所有画面模仿相同色板、饱和度和笔触密度。

## 3. 生成时怎样避免照抄名画

1. 先取 `cases.json` 每幅原画对应的 `content_prompt`，固定完整提示、画幅、要求；要求同类场景，但不强求对应原作的物体数量、具体位置或人脸。
2. **原作图像只给评审者看（EVALUATION_ONLY），不作为这幅画的内容图输入。**否则很难区分模型真的有画法能力，还是只照抄了原画的像素、构图与对象。
3. Baseline 与候选 Skill 应使用相同内容提示、同一宿主模型与尺寸，尽可能锁定参数、参考图角色、时间窗口；候选可使用其已冻结的独立 style anchor，但要记录该锚点，不能声称对照只改变某一句提示词。
4. 需要评测独立画风配方时，可增加纯文本配方臂；但这是**另一个预登记实验**，不把方法和条件偷偷改变后的图混进当前比较。
5. 不固定 seed 或模型版本的后端，记录真实可获得字段，按同一时段交错生成；不得伪造精确复现。

**首轮建议：** 3 幅内容题目 × 2 个方案 × 每方案 1 次 = 6 张冒烟样本。确认能产出独立画作并可看图后，才扩大为 3 × 2 × 2 = 12 张（**合计是否重新生成**需在执行前声明），不自动使用付费 API，也不自动批量挑最好的一张。

## 4. 每幅作品的审看顺序

1. **核对图像本身**：确实是生图工具返回的独立画作，非报告、合成拼图或原画复制品；留存模型/调用记录、尺寸、输出 SHA-256。
2. **内容门槛**：题材类别、光照/天气和单幅格式必须通过。未评审填 `null`，看不清记 UNKNOWN，不给正常分。
3. **评审遮蔽**：对候选随机编号，尽量隐藏 Baseline/Skill 版本；以固定的原作参考展示进行人工对照，不让模型先看到哪个是“优化后”。
4. **分别打四维分数**：每项写至少一句具体画面证据，包括颜色/笔触所在区域，而不只是“很像莫奈”。不要把漂亮程度当成画风贴合程度。
5. **记录失败局部**：标注位置（天空、水面、衣物、草地、麦垛），区分重复鳞纹、过度饱和、全部磨糊、色彩关系不自然等。
6. **结果排序**：先看硬性失败数量，再看各维度与加权分、跨题材波动；全部图都保留，不做只挑好图的 best-of-N 作弊。

### 四维评分锚点

**对应题材的经核实莫奈原作，四维均定义为 10 分。** 这是本项目的风格比较基准，不是宣称不同原作的笔触密度、厚涂、完成程度均相同，也不要求复制原作构图或签名。原作的定义分写在 `original_reference.definition_scores`；生成图的分数仍写在 `scores`，未经评审必须为 `null`。原作不能作为“满分生成样本”进入实验均值。

1.1.0 记录实际看过的原作复制图：馆藏号与馆方入口须匹配该用例，另填写该复制图的来源 URL、本地路径、SHA-256。不能只看研究文字就勾选 `inspected_original=true`；换了复制图要重记来源与哈希。代码核对声明、文件和身份字段，不能自动证实摄影来源的真实性或画面判断的正确性。

| 维度 | 局部观察要求 | 不应当作改进 |
|---|---|---|
| 笔触组织 30% | 比较至少两个区域的尺度、方向、密度与连续性；联系形体、受光、距离和重要性；人物与环境的完成程度是否协调 | 所有区域统一长笔/粗笔；把人物糊掉；随机增加笔触 |
| 色彩关系 30% | 检查亮部、阴影、周围色域及局部焦点；有水面时关联反射来源 | 全局蓝紫滤镜；单纯增加饱和度；继承锚点天气而违背请求 |
| 空气氛围 30% | 结合遮挡、尺度、对比、边缘和色彩连续性判断空间；允许明朗日光中的清晰主体 | 全图模糊；平均删减细节；把所有天空画成雾 |
| 机械鳞纹控制 10% | 寻找无视结构、照明、距离的同大小/同间距重复纹理，指出实际位置 | 把花群、叶片、窗洞的结构性重复一律删除；把真实破碎短笔当错误 |

| 分数 | 解释 |
|---:|---|
| 0–2 | 明显不符合原画的画法语言、严重机械纹理或无空气组织 |
| 3–4 | 存在一些印象派元素，但更多是滤镜、均匀小碎笔或固定色板 |
| 5–6 | 部分自然，但颜色、笔触、边缘或空间明显偏离 |
| 7–8 | 整体具有可迁移的色彩与绘画逻辑，瑕疵有限 |
| 9–10 | 高度连贯，区域差异、光色空气关系都经得起局部查看 |

分数为**评审意见，不是艺术史鉴定值**；若 `hard_gates` 均通过且四维都有真实评审，则：

`S = 0.30 × 笔触 + 0.30 × 色彩 + 0.30 × 氛围 + 0.10 × 伪纹理控制`

**禁止**仅因为 S 高就宣布“稳定”。每张图还要报告四项原始分、失败区域和分歧。首次试验不预设“分数多少一定可以发布”。

### 签名与独特构图检查

`reference_leakage_review` 分别记录 `signature` 与 `distinctive_composition` 的 pass / fail / unknown 及局部证据。此处 pass 表示该项未见明确迁入；fail 表示有明确问题；看不清或未看用 unknown。

- 查看四角及其他疑似文字区域；保留宿主规定的溯源标记，不能把删除提供方溯源当作优化。
- 比较房屋、树干、地平线、对象位置组合等是否搬运了原作独特布局。用户本来要求树或房屋时，共享这类对象本身不是泄漏证据。
- 区分风格相似、构图模仿、像素复制。仅凭视觉相似不能宣称逐像素复制；文件哈希相同只能证明同一文件。1.1.0 拒绝把正在对照的原作文件当生成图提交，但哈希检查不能发现所有裁切/重编码复现。
- `hard_gates.reference_leakage=true` 仅在上述两项均 pass 时填写；任一 fail 为 false；否则为 null。任何硬门 fail/unknown 时，四维分数必须保持 null，不计算总分。

## 5. 单轮优化决策

每次只选一个有证据的缺陷，例如“港口水面的鳞纹密度过高”。随后：

`冻结旧版 → 预登记变更 → 仅改有关规则 → 同题同参数 A/B → 各项评审 → 保留/回滚/不确定 → 收集失败证据`

- **笔触失败**：检查天空/水面/衣物等是否使用同尺度短笔，尝试修改区域级笔触规则，而非全图加粗笔触。
- **色彩失败**：比较高饱和焦点与周围色域的关系，不单纯拉高/压低全局饱和度。
- **氛围失败**：检查边缘消融、远近对比、冷暖层次，避免全图无差别柔焦。
- **纹理失败**：记录鳞纹所在区域及尺度，试最小改动；使用 clean-remake 时不要破坏正确的空气感。
- **内容失败**：先修宿主/内容约束；图片根本不是单幅画的情况视作工具路由错误，而非画风低分。

小样只用于选择下一轮方向，不能当作统计学上的“稳定提升”。晋级后再用不同题材、不同原作的**作品级独立保留集**做验证；原作不同扫描和裁切不得跨开发/保留集。保留集一旦拿来调参，就转为开发集，不能继续用于盲测。

## 6. 记录规范与状态

每张图复制 [review-template.json](review-template.json) 一份，填入真实 `case_id`、输出地址/哈希、实际查看的原作来源、使用的模型及能取得的配置、评审人、硬门结果、四维分数及画面证据。若没有生成图片，`generation_performed=false`、输出信息和四维分数保持 `null`、状态必须是 `NOT_RUN`。

同一图片的人评与模型评保存为**独立记录**，明确 `reviewer.kind`、身份、是否查看原作/输出、是否知道实验臂；分歧保留，不用模型分覆盖人评。A/B/C、P2、P3、P4 等历史样本条件不同，不与新协议分数拼成“稳定上升”曲线；P5 没有实际样本时不补造分数。

**禁止再次发生**：用信息图代替实际画作、从虚构比较表中产生评分、将尚未测试的结果写成“通过”、把内容与风格相似度混在同一个总分中。

本协议与上层 [优化循环](../../docs/optimization/README.zh.md) 配合使用。旧五维 0–4 记录按原协议保留，新原作对照采用本文四维 0–10；不机械换算旧分。研究驱动的新版 Skill 是新的待验证输入，不能用协议/代码测试通过代替视觉验证。

## 7. 生图请求隔离与真实错误归因（2026-11-10 修订）

近期发生过两类被错误报告为“第三方相似性限制”的情况：一类是生图工具参数校验失败（包括把无效动画参数送进静态图请求），另一类在会话中根本没有可核实的实际工具拒绝记录。**这不能用来断定莫奈风格被禁止，也不能把未知错误称作真实的提供方审核拒绝。**

执行前运行：

```bash
python3 benchmarks/original-paintings-v1/generation_preflight.py prepare --case MOR-01 --profile research-v3 --output /tmp/monet-mor01-prompt
```

预处理现在调用正式 Skill 的 `monet.prepare(..., text_only=True)`，不再维护另一份 `STYLE` 配方。默认 `--profile research-v3 --variant baseline`；正文与正式编译器一致，`prompt_sha256` 为正文哈希，`prompt_file_sha256` 另计文件末尾换行。`style_lock` 中的锚点是选定配置，**此纯文本路线没有实际附上锚点**：`style_anchor_attached=false`、`controlled_ab_qualified=false`，准备提示词不能证明受控 A/B 条件成立。

`regional-p0` 仅允许搭配历史 `legacy-v2`。历史 profile 保留带参考角色/对象信息的旧正文时，本 benchmark 会明确拒绝发出，不暗中清洗后冒充相同历史配方。历史复现应使用已冻结的旧提交和协议；全新版与旧版的整体比较属于组合更新比较，不能归因到某一句规则。

实际需要测试时，只把 `image-only-prompt.txt` 的**完整文字**复制到用户的独立生成对话；`generation-metadata.json`、原作名称、馆藏 URL、评分量表和前一轮失败报告留在评测器一侧。原作只用于生成**之后**的风格对照，不把目标画的像素作为生成参考，也不要求原作级构图复刻。新对话是人工隔离措施，不证明服务端模型/参数已锁定。生成内容仍必须属于用户指定题材并符合真实服务政策，不能以改写提示的方式规避真正的安全拒绝。

当前三个用例仍为跨时期诊断。后续验证默认 1880s 时，应另行预登记花园、坡地/海岸、建筑与植被等同范围题材；只选一个明确问题，固定可得条件、保留全部首轮输出并分别人评/模型评。未实施前不填写输出数或分数，不借本次修改启动自动实验。

如调用失败，先保留原始工具证据，再分类：

- **NO_TOOL_CALL_EVIDENCE**：没有对应的生图工具调用；不能宣称是版权或模型审核拒绝。
- **TOOL_ARGUMENT_ERROR**：工具参数或输入验证失败；纠正 API/模式/画布等参数，不改成“版权原因”。
- **PROVIDER_REFUSAL_RECORDED**：只有工具实际返回提供方策略拒绝记录时才使用，须保留脱敏的原始错误信息；不猜测具体策略规则。
- **GENERATED_PENDING_VISUAL_REVIEW**：确有图片输出，但尚未按画面内容和风格评审，不能假装质量通过。
- **TOOL_ERROR_UNCLASSIFIED**：其他/来源未明的真实工具错误，应如实记录。

可用 `generation_preflight.py diagnose --record attempt.json` 校验手动记录的尝试状态。此脚本没有生图能力，也**不可能**直接改变平台审核规则；它只避免输入混淆、错误归因和不实结果报告。

测试：`python3 -m unittest discover -s benchmarks/original-paintings-v1 -p 'test_*.py' -v`。
