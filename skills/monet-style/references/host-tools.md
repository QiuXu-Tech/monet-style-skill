# 任务模式与宿主工具

Skill 提供绘画决策、提示编译和评审流程，不自带生图模型。`monet.py`不会调用图像生成器；`prepare`只准备文字、记录和在显式cleanup时所需的辅助参考。

## 先应用用户授权

| 任务或能力 | 行为 |
|---|---|
| 用户只要提示词，或项目要求另开对话生图 | 完整纯文本直接放在对话中，不调用生图，不自动交付TXT/ZIP |
| 用户要求研究或评审 | 查看真实原作/返回图；不自动转为生成或重绘 |
| 用户明确请求实际图像，且当前会话允许 | 再核对真实工具schema与图片输入能力 |
| 支持真实风格图像输入 | 查看、校验并传入正确像素；不要以URL代替附图 |
| 同时支持内容图与风格图 | 可以按各自角色转绘；保留用户主体和结构 |
| 支持多参考且角色可区分 | 必要时使用cleanup结构图与光色辅助，不能假装模型有未暴露的绑定参数 |
| 无生图能力或不支持必要角色 | 如实说明受控生成不可用；已请求的文本工作仍可完成 |
| 返回图无法查看 | 保持未审看状态，不填写通过或分数 |

在本项目研究对话，用户持续要求实际测试图由其在独立对话中生成；升级Skill不自动取消这一要求。不要调用替代模型、付费API或本地GPU来绕过任务范围。

## 准备、传入和审看分别记录

`job.json`区分已准备的本地参考与实际传输。`prepare`之后，`generation_performed=false`，`style_anchor_attached=false`；风格图片存在不意味着任何模型已收到它。纯文本模式允许存在cleanup辅助图，因此不能用“参考列表非空”推断style-only原图存在。

实际执行时，应通过宿主支持的附件机制确认每个必需角色。评审中对应的交付检查保持unknown，直到实际调用记录或附件证据支持通过。此类记录仍是操作者报告，脚本不会认证远端模型是否采纳参考。

对于用户从其他聊天带回的图片，未知模型ID、种子和附图情况照实写未知。图像可进行观察评审，但不能宣称同模型同参数的严格受控试验。

## 使用当前工具的真实接口

在允许生成的宿主中，优先使用用户已有的图像工具，不要求用户额外付费或安装模型。通过当前schema确认真实可用的prompt、图片路径/引用、画幅等字段；不假定支持seed、精确模型版本、ControlNet、IP-Adapter或角色权重。

宿主若从上下文理解指令，只传递本次完整绘画要求，避免旧场景、评分、研究报告和来源标题干扰。用户另开干净聊天可缓解上下文混入；不能宣称已经验证服务端隔离或固定随机过程。

如宿主要求生成后停止，遵守该要求，保留候选待评审；不虚构紧随其后的看图。宿主的安全和来源标记要求继续适用。

## 可选本地执行器

[explicit-comfyui.md](explicit-comfyui.md)描述现有可选适配器。仅当用户明确要求使用已配置的本地环境时启用；默认dry-run，实际提交需要`--execute`。它不安装模型、不提供GPU，模拟后端测试不等于真实推理通过。本项目本轮不执行该路径。

静态安装和宿主说明见[sources.md](sources.md)中官方来源；具体能力以当前环境为准，不能凭旧核查日期保证接口仍相同。
