# Monet Style

Use the researched painting relationships to make decisions about this scene. Keep the generation prompt focused on the painting; keep sources, scores and execution records outside it. Treat this as an experimental Skill: **research-informed instructions are not demonstrated image-quality improvements.**

## 1. Choose the task before choosing a tool

| User's task | Action |
|---|---|
| Prepare a prompt / plan an experiment | Return one complete, copyable plain-text prompt in chat. Do not call an image tool or deliver TXT/ZIP unless asked. |
| Review a supplied image | Open the actual image and use [review.md](references/review.md). Do not generate a replacement automatically. |
| Study an authentic artwork | Use [artwork-evidence.md](references/artwork-evidence.md) and primary museum sources; separate facts, visual observations and hypotheses. Do not silently change the Skill. |
| Create or restyle an image in a session that permits it | Check [host-tools.md](references/host-tools.md), then use the actual supported image tool. |

Apply persistent session constraints first. **In the Monet Style Skill project research conversation, actual tests are generated by the user in separate conversations. Prepare prompts and review returned images here; do not call image generation.** Having a tool available does not override this constraint. A request to upgrade the Skill does not authorize a visual experiment.

`PROMPT_ONLY` is a legitimate delivery mode. It does not require image-tool access or a downloaded anchor. If local Python is unavailable, compose the requested prompt from the same written contract, state that compilation/hashes were not checked, and do not invent a run record.

## 2. Set scope and preserve the brief

Read [painting-language.md](references/painting-language.md). Default to `research-v3`, contract 0.3.1 (paint-constructed forms), profile `monet-1880s-research-v3`, with `antibes-1888` as the registered style anchor. `research-v3-previous` preserves the exact 2026-11-18 core for comparison; never silently reuse an old series lock. Use `pourville-1882` only when explicitly chosen. Keep the anchor stable across subjects in a series.

The closest research for this default is 1881/1882/1888. Use 1870s and 1890s studies for qualified comparisons and counterexamples, not to import their palette, composition or surface into every task. If a user explicitly requests another period, provide a clearly labeled research-based text proposal when the available studies support it; do not compile it under the 1880s profile or claim a validated era preset. For late large Water Lilies, explain the current research gap instead of relabeling the default.

Retain the original request verbatim. Extract observable `must_keep`, `must_avoid`, aspect ratio and image mode. Preserve count, action, identity, object relationships, weather and time. Use `mode: restyle` only with a real user-supplied image. Do not replace a difficult modern subject with a cottage, cathedral or garden from a reference.

Resolve routine artistic choices without unnecessary questions. Surface a material conflict such as an exact photographic face requirement together with an extremely small, simplified figure; keep the user requirement intact while explaining the tradeoff.

## 3. Plan the painting in relationships

Use [painting-language.md](references/painting-language.md) for scene planning and [artwork-evidence.md](references/artwork-evidence.md) for evidence and exceptions. Do this briefly before writing the prompt:

1. Identify the large masses, main planes, overlaps and the features that make the requested action readable. Ensure colour strokes and paint masses construct these forms instead of serving as a decorative overlay.
2. Establish the requested illumination and broad light/shadow relationships. Decide which edges and details the light makes prominent or recessive.
3. Compare the important regions: form, material, distance, visual role, stroke direction/scale/concentration, and useful quiet passages. Include differences within one material where needed.
4. Keep detail proportional to scale and purpose. Preserve small figures through posture, proportions and colour relationships; keep hands/actions intelligible without miniature polish or anatomy errors.
5. Distinguish mark visibility from apparent paint relief. Do not prescribe global thick paint, forced fog, uniform blur, random noise or fabricated aging.

This is a planning method, not a reconstruction of Monet's literal working sequence. Allow shared rhythms and decorative passages; do not require every stroke to describe a separate physical object.

Select **zero to three** relevant modules from [subject-modules.json](references/subject-modules.json): `garden`, `water`, `figures`, `architecture`, `snow`, `coast`. Choose only for elements already in the brief. These are conditional instructions within the profile, not new era presets. Do not append all modules.

Use optional `painting_notes` for at most five short, scene-specific relationships that the core and modules do not already express. For example, connect a path's warm light and cool shadow to its receding plane, or retain a figure's hand/umbrella contact. Do not put source titles, fixed museum layouts, scores, technical pigment names or unverified material sequences in these notes.

## 4. Compile and deliver

Find the directory containing this file as `SKILL_ROOT`. Keep private task files outside the installed Skill and public repository. See [garden-figures.json](examples/garden-figures.json) and [river-evening.json](examples/river-evening.json) for the request schema.

```bash
python3 "$SKILL_ROOT/scripts/monet.py" check
python3 "$SKILL_ROOT/scripts/monet.py" prepare --request request.json --text-only --out monet-run-001
```

For a prompt-only request, paste the complete `prompt.txt` contents into chat. Do not make the user download the file. Keep `job.json`, hashes, reference status, scores and source history outside the image prompt. Explain any important limitation separately and briefly.

The core painting language has one canonical source: [style-contract.json](references/style-contract.json). The compiler appends only the chosen modules and scene notes. Do not maintain another independent painting passage in a benchmark or silently rewrite the fixed passage during an experiment.

For an authorized reference-controlled run, fetch and open the selected reference before preparing without `--text-only`:

```bash
python3 "$SKILL_ROOT/scripts/monet.py" fetch --anchor antibes-1888
python3 "$SKILL_ROOT/scripts/monet.py" prepare --request request.json --out monet-run-002
```

`prepare` never generates images or silently downloads references. A verified local reference is **prepared**, not proof its pixels reached a model. Confirm actual attachments through the host's supported mechanism. Treat content, style and any cleanup helpers as distinct roles; a URL in prose is not an attached image. Never claim a reference is attached merely because cleanup helper files exist.

To continue a series, pass `--lock previous-run/style-lock.json`. Reject changed profile, anchor, rule-library or version hashes. Topic-module selection and scene notes can vary with content while the rule library stays fixed; compare exact job/prompt hashes when testing. Input locks do not control undisclosed model versions or guarantee pixel reproducibility.

## 5. Generate only on the authorized route

Inspect the actual content image and style reference. Read the job and map only supported parameters into the real tool schema. Do not invent model IDs, seeds, image-binding controls or paid backends. Keep the original request authoritative for subjects and illumination.

Request one full-canvas original painting when one is requested. Avoid comparison grids, reports, labels, invented scores and imitation signatures. Check for distinctive reference layout borrowing as well as copied objects. A shared requested tree, building or river is not by itself copying. Preserve provider provenance requirements.

If previous outputs or evaluation text have contaminated a generation context, keep the new brief isolated and ask the user to run it in a fresh conversation when that is their workflow. A user-reported fresh conversation is a mitigation, not a verified backend control or strict A/B experiment.

Use the optional [clean-remake route](references/clean-remake.md) only for a supplied image with a diagnosed texture problem and compatible role controls. Its helpers are not finished paintings or a default blur treatment. Use the [local ComfyUI runner](references/explicit-comfyui.md) only when specifically requested and already configured; it remains dry-run by default. Do not install models or switch services merely to continue this project.

## 6. Review what actually exists

Read [review.md](references/review.md). Inspect the whole image, major regions and selected close details including corners and focal faces/hands. Separate normal structural repetition from mechanical stamping. Verify content and original composition before calculating a style total.

Use the corresponding verified original as the **definition anchor of 10/10** in each dimension: brushwork 30%, colour 30%, atmosphere 30%, mechanical-texture control 10%. Record human and model assessments independently. Missing images, unknown gates or missing comparison evidence mean no valid total; never infer a score from a prompt.

For a locally prepared job with an available candidate:

```bash
python3 "$SKILL_ROOT/scripts/monet.py" inspect --image candidate.png
python3 "$SKILL_ROOT/scripts/monet.py" review --job monet-run-001/job.json --image candidate.png --assessment filled-review.json --out result.json
```

The script records supplied pass/fail/unknown observations and checks consistency; it does not perform aesthetic vision or calculate the four-dimension comparison. Record that comparison separately following the review guide. A reference-free output remains reference-free even after favorable review. For a user-returned image without a matching job, review it directly and record missing generation metadata honestly instead of fabricating a job/call ID.

Correct one diagnosed problem at a time. Do not automatically regenerate while reviewing. When generation is permitted, limit actual attempts to the authorized budget, at most three per task. Preserve all candidates and failure evidence. Treat this release as a research-informed rule update with **visual validation pending**, not a proven gain or a stable final Monet model.
